# 07 — 权限与安全边界

Host API 受权限、宿主授权、当前触发上下文和运行时策略共同限制。插件开发时不要假设声明了权限就一定能调用成功。

## 权限声明格式

`manifest.json` 的 `permissions` 字段必须存在。需要受控 Host API 时，添加权限对象：

```json
{
  "permissionId": "call_model",
  "title": "调用模型",
  "description": "允许插件通过宿主模型服务发起受控 LLM 调用",
  "riskLevel": "HIGH",
  "required": true
}
```

| 字段 | 说明 |
|------|------|
| `permissionId` | 权限 ID |
| `title` | 用户可见标题 |
| `description` | 用户可见说明 |
| `riskLevel` | `LOW` / `MEDIUM` / `HIGH`，默认 `MEDIUM` |
| `required` | 是否必需，默认 `true` |

## Host API 权限表

| permissionId | 覆盖能力 |
|--------------|----------|
| `network_request` | `hostApi.fetch`、`hostApi.network.request` |
| `provider_read` | `hostApi.providers.list`、`hostApi.providers.models` |
| `send_message` | `hostApi.message.send` 的普通文本 / 附件发送 |
| `rich_message_send` | `hostApi.message.send({ chain })` 富消息链 |
| `conversation_read` | `hostApi.conversation.history` |
| `call_model` | `hostApi.callLlm`、`hostApi.llm.generate` |
| `context_compress` | `hostApi.context.compress` |
| `schedule_manage` | `hostApi.registerScheduledHandler` |
| `message_stream` | `hostApi.message.openStream` 及 stream 操作 |
| `agent_run` | `hostApi.registerAgent`、`hostApi.agent.run` |

无需权限的基础能力：

- message / command / regex handler 注册。
- lifecycle / LLM hook / tool / tool lifecycle 注册。
- `hostApi.log`。
- `hostApi.getPluginMetadata`。
- `hostApi.getSettings` 及等价方法。
- `hostApi.storage.plugin` / `hostApi.storage.session`，但 session scope 需要当前会话。

## 权限判定链路

受控 Host API 调用会依次检查：

1. `manifest.json` 是否声明了该 `permissionId`。
2. 用户或宿主治理是否授予该权限。
3. 当前触发上下文是否允许该权限。
4. 宿主运行时策略是否允许本次调用。

失败时通常返回：

```javascript
{
  ok: false,
  error: {
    code: "permission_denied",
    message: "Permission denied for host API.",
    details: {
      api: "hostApi.fetch",
      permissionId: "network_request",
      gate: "user_grant"
    }
  }
}
```

## 网络安全边界

网络请求只能走宿主代理：

```javascript
await hostApi.fetch({ url: "https://api.example.com/ping" });
```

同时必须：

- 在 `manifest.json` 声明 `network_request`。
- 在 `android-plugin.json` 声明 `network.allowedDomains`。
- 只访问 `http` / `https`。
- 不访问 localhost、私有 IP、`.local`、`.internal`、`.lan`。
- 不依赖重定向绕过白名单。

不支持插件自行打开 socket、执行 subprocess、访问 Node.js 网络库或直接调用 Android 网络 API。

## LLM 与 Agent 边界

- `hostApi.callLlm`、`hostApi.llm.generate`、`hostApi.context.compress` 和 Agent 内部 LLM 调用默认绕过插件 LLM hooks。
- 插件不能通过 LLM hook 递归拦截自己发起的直接 LLM 调用。
- Agent 工具调用由宿主 tool loop 控制；插件工具不要伪装宿主保留来源。
- 保留前缀包括 `mcp.`、`skill.`、`web.`、`active.`、`ctx.`、`context.`。

## 会话边界

这些 API 要求当前消息会话：

- `hostApi.message.send`
- `hostApi.message.openStream`
- `hostApi.conversation.history`
- `hostApi.context.compress`
- `hostApi.storage.session`

如 API 支持 `conversationId` 参数，该参数只能省略或等于当前事件会话 ID。不能跨会话读取历史或发送消息。

## 当前不支持能力

以下能力当前不属于插件开放 API：

- Web API 注册。
- 平台适配器注册。
- 宿主数据库直连。
- 文本转图。
- HTML 渲染。
- 任意文件系统访问。
- Node.js / npm 运行时。
- 旧式 `activate(hostApi)`、`registerCommand(...)`、`onDecoratingResult(...)` 简写 API。

开发时如遇到这些需求，应改用现有 Host API 降级，或在插件说明中标记为宿主暂不支持。
